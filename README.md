# クリックジャッキングのデモ

透明な iframe を使い、「景品を受け取る」をクリックすると架空の SNS プロフィールが全体公開になるデモです。公開範囲は被害側サーバーで実際に変更します。外部サービスには接続しません。CSS は配置・重なり・可読性に必要なものだけです。

## 起動

Node.js 24 と pnpm 11 を用意してください（`mise install` でも準備できます）。

```sh
pnpm install
pnpm dev
```

[http://127.0.0.1:5173](http://127.0.0.1:5173) を開きます。被害側サーバーも自動的に起動します。両サーバーともループバックだけで待ち受けます。5173 / 5174 番ポートを空けておいてください。終了は Ctrl+C です。

ビルド後の動作確認も可能です。

```sh
pnpm build
pnpm preview
```

この場合は [http://127.0.0.1:4173](http://127.0.0.1:4173) を開きます。被害側は同じ 5174 番ポートを使用するため、`dev` と `preview` は同時に起動しないでください。静的ファイルの配信だけでは被害側サーバーは動作しません。

## 発表の手順

1. 「対策なし」「不透明度 0%」を選びます。必要なら「非公開に戻してやり直す」を押します。
2. 「景品を受け取る」をクリックします。結果欄が「非公開」から「全体公開」に変わり、処理回数と時刻が表示されます。更新まで最大約 0.7 秒かかります。
3. リセット後、不透明度を 50% にします。罠のボタンと被害ページの「プロフィールを全体公開する」が重なっていることを見せます。100% では被害ページが見えます。
4. CSP / X-Frame-Options: DENY / SAMEORIGIN を選びます。切り替え時に自動でリセットされます。同じ場所をクリックしても「非公開」のままです。
5. 不透明度 100% で埋め込み拒否表示を確認します。ブラウザーによっては空白やエラーアイコンになります。開発者ツールの Console で拒否理由、Network で `/account?protection=...` のレスポンスヘッダーを確認できます。
6. 「被害ページを別タブで開く」では対策ありでも通常の操作が可能です。埋め込みだけが拒否されることを説明できます。

## 実装

| 役割                   | 開発時のオリジン        | 内容                                                                 |
| ---------------------- | ----------------------- | -------------------------------------------------------------------- |
| 罠・発表用コントロール | `http://127.0.0.1:5173` | React、透明 iframe、不透明度・対策切り替え、結果表示                 |
| 架空 SNS               | `http://127.0.0.1:5174` | Node.js HTTP サーバー、ログイン相当の Cookie、公開フォーム、状態管理 |

ポート番号を分けているため別オリジンです。罠ページの JavaScript は iframe の DOM を読み書きしません。被害ページの本物のフォームが、利用者のクリックで POST されます。送信元 Origin と CSRF トークンを検証しても、被害ページ自身による正規の送信なので成功します。

デモ用のセッションを Cookie（HttpOnly / SameSite=Lax）で識別し、認証手順は省略しています。状態はブラウザーセッションごとにサーバーのメモリへ保存し、サーバー再起動で消えます。同じ Cookie を使う複数タブでは状態を共有します。

対策は被害ページの **HTTP レスポンスヘッダー** として返します。meta タグによる代用はしていません。

| モード     | ヘッダー                                          | このデモでの結果                  |
| ---------- | ------------------------------------------------- | --------------------------------- |
| 対策なし   | なし                                              | iframe が表示され、クリックで公開 |
| CSP        | `Content-Security-Policy: frame-ancestors 'none'` | 埋め込み拒否                      |
| DENY       | `X-Frame-Options: DENY`                           | 埋め込み拒否                      |
| SAMEORIGIN | `X-Frame-Options: SAMEORIGIN`                     | ポートが異なるため埋め込み拒否    |

結果表示とリセットには、発表用に限定した `/api/state`・`/api/reset` と CORS 許可を用意しています。CSRF トークンは観測 API に含めません。この観測機能は攻撃の成立には不要です。

この構成は **別オリジン・同一サイト** なので SameSite=Lax の Cookie も iframe に送信されます。実際の別サイト間では SameSite や第三者 Cookie の制限により挙動が変わります。SameSite の比較を目的としたデモではありません。対策をクエリパラメーターで選べる仕組みも教材専用です。

主なファイル：`src/App.tsx`（発表画面）、`src/style.css`（最小限の CSS）、`server/demo-server.ts`（被害サービスと起動用 Vite プラグイン）。

## 検証

```sh
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test
pnpm build
```

自動テストでは実際の HTTP サーバーを起動し、ヘッダー・公開処理・CSRF / Origin 検証・セッション分離・リセット・観測 API の制限を確認します。iframe の拒否自体は上記の手順でブラウザーでも確認してください。
