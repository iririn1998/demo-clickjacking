# クリックジャッキング デモ（モノレポ）

クリックジャッキング（Clickjacking / UI redress）を体験するための教育用デモです。
被害側の「退会（アカウント削除）」ボタンが、攻撃側の透明な `iframe` を通じて、
利用者の意図しないうちに押させられる様子を再現します。あわせて、
`X-Frame-Options` や `Content-Security-Policy: frame-ancestors` といった防御が
攻撃を無効化する様子も切り替えて確認できます。

> ⚠️ これは防御手法を学ぶための無害なローカルデモです。両サーバーはループバック
> (`127.0.0.1`) だけで待ち受け、外部サービスには接続しません。実在するサイトや
> 他人のアカウントに対して、この手法を試してはいけません。

## 構成（pnpm workspace モノレポ）

| パッケージ          | 役割   | 開発時のオリジン        | 内容                                                                       |
| ------------------- | ------ | ----------------------- | -------------------------------------------------------------------------- |
| `packages/victim`   | 被害側 | `http://127.0.0.1:5174` | SecureBook。ログイン・アカウントページ・退会ボタン。防御ヘッダーの切替。   |
| `packages/attacker` | 攻撃側 | `http://127.0.0.1:5173` | 偽の「当選」ページ。透明 iframe で被害ページを重ね、退会ボタンを押させる。 |

どちらも Node.js 標準の `http` モジュールだけで書かれており、ランタイム依存は
ゼロです。TypeScript は Node のネイティブな型ストリッピングで直接実行します
（ビルド不要）。

```
packages/
  victim/src/    server.ts / pages.ts / store.ts (+ server.test.ts)
  attacker/src/  server.ts / page.ts            (+ server.test.ts)
scripts/dev.mjs  2つのサーバーを同時起動するランチャー
```

## 必要環境

- Node.js 22 以上（型ストリッピングを使用。CI は Node 24）
- pnpm 11（`mise install` でも Node / pnpm を用意できます）

## 起動

```sh
pnpm install
pnpm dev
```

- 攻撃側（デモの入口）: <http://127.0.0.1:5173>
- 被害側（SecureBook）: <http://127.0.0.1:5174>

個別に起動する場合は `pnpm dev:victim` / `pnpm dev:attacker` を使います。
5173 / 5174 番ポートを空けておいてください。終了は Ctrl+C です。

## デモの手順

1. 攻撃側ページ <http://127.0.0.1:5173> を開きます（左に発表用の操作パネルがあります）。
2. パネルの「ログインページ」から被害側を開き、**alice / password123** でログインします
   （入力済みなのでそのままログインできます）。
3. 攻撃側のタブに戻ります。パネルの状態表示が「ログイン: はい」に変わります。
4. 防御設定が「なし（脆弱）」のまま、中央の緑のボタン **「景品を受け取る」** を押します。
5. パネルの状態が「有効 → 削除済み」に変わります。**クリックジャッキングで退会させられました。**
6. 「アカウントを復活（リセット）」を押し、もう一度ログインします。
7. 防御設定を **`X-Frame-Options: DENY`** や **`CSP: frame-ancestors 'none'`** に変更します。
   フレームの読み込みがブラウザーに拒否され、同じ操作をしても退会されません（攻撃失敗）。

途中で「被害ページの不透明度」スライダーを上げると、緑のボタンの真下に被害側の
赤い「退会する」ボタンが重なっている仕掛けが見えます。「クリック位置の目印を表示」で
クリックされる領域も確認できます。

## 攻撃の仕組み

- 攻撃ページは被害ページ（`/account`）を **`opacity: 0` の透明な iframe** で最前面に重ねます。
- 見た目の「景品を受け取る」ボタンは**おとり（decoy）**で、その真上に透明な被害側の
  退会ボタンが配置されています。クリックは最前面の iframe に届くため、実際には
  被害側の退会ボタンが押されます。
- 退会リクエスト（`POST /account/delete`）は**利用者自身のブラウザー**から、
  **利用者自身のセッション Cookie** 付きで送信されます。攻撃サーバーは Cookie に
  一切触れません。これがクリックジャッキングの本質です。
- 退会フォームは被害サイト本物のフォームなので、**CSRF トークンがあっても防げません**。
  だからこそ「フレームに埋め込ませない」防御が必要になります。

## 防御（このデモで確認できるもの）

| 設定                                              | 効果                                                   |
| ------------------------------------------------- | ------------------------------------------------------ |
| `X-Frame-Options: DENY`                           | どのサイトからのフレーム埋め込みも拒否。               |
| `X-Frame-Options: SAMEORIGIN`                     | 同一オリジンからの埋め込みのみ許可。別オリジンは拒否。 |
| `Content-Security-Policy: frame-ancestors 'none'` | 現在推奨の方法。埋め込みを拒否。                       |

被害側は `/account` と `/account/delete` のレスポンスに、選択したモードのヘッダーを
付与します。開発者ツールの Network タブでレスポンスヘッダー、Console で拒否理由を
確認できます。実運用ではこれに加えて、退会のような重要操作は Cookie に `SameSite`
属性を付け、再認証（パスワード再入力）を挟むのが定石です。

## ブラウザーに関する注意

被害側 Cookie は `SameSite=Lax` です。`127.0.0.1` の別ポート同士は同一サイト
（same-site）扱いのため、iframe 内のリクエストにも Cookie が送られ、デモが成立します。
一方で別オリジン（別ポート）なので、`SAMEORIGIN` や `frame-ancestors` による
埋め込み拒否はきちんと機能します。サードパーティ Cookie を厳しく制限する設定や
プライベートウィンドウでは挙動が変わることがあります。
